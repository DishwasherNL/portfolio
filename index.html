About this project

A real-time operator interface for hydrogen fueling stations, built in Ignition Perspective. It covers filling bay control, P&ID visualization, and a PackML-based state machine — the primary interface between operator and station hardware.

My role

Lead designer and front-end developer. Responsible for the full HMI architecture, component design, and Ignition Perspective implementation — from tag structure and UDT definitions to P&ID views and state machine visualization.

S

Resato's new hydrogen fueling stations had no standardized operator interface. Engineers relied on PLC diagnostics and separate documentation to monitor station states.

T

Design and build a complete HMI MVP covering filling bays, P&ID views, and PackML state machine visualization — ready for live deployment before September 2026.

A

Designed the component architecture using UDTs, built P&ID symbols to ISO 10628-2 standards, defined the style class system, and implemented the full state machine view in Ignition Perspective.

R

MVP delivered on schedule. Operators can monitor and control all station states from a single interface, cutting fault identification time significantly.

< 1 min Fault identification (was 5–10 min)
On time MVP delivered before Sept 2026
ISO 10628-2 P&ID symbol compliance

About this project

An internal web platform that gives commissioning engineers a single environment to configure, validate, and document hydrogen station setups — deployable to both staging and production via Docker. Currently entering beta field testing.

My role

Front-end developer. Responsible for the full UI, environment-aware deployment setup, and API integration. Collaborated with SBEC (backend) and EBRO (test automation).

S

Engineers spent 6–8 hours of direct, uninterrupted time per commissioning report using spreadsheets and manual checklists to configure and validate hydrogen stations on-site — an average of 7 hours, or roughly €350 in labor cost per report at a fully loaded rate of €50/hour.

T

Build the front-end for a unified commissioning platform that works across staging and production environments and supports engineers in the field.

A

Documented the functionality in a functional specification, wrote a test plan to validate the tool methodically, and built the UI in vanilla HTML/CSS/JS with Docker deployment for both environments. The first test round uncovered a technical issue, which was diagnosed and fixed, then successfully re-verified in a second round with minor advice points.

R

Two independent report-generation tests (7 min 20 sec and 9 min 40 sec, averaging 8.5 minutes) show a 98% reduction in direct time per report — down from 7 hours to 8.5 minutes, or from €350 to roughly €7 in labor cost. The tool is now moving into beta field testing.

-98% Direct time per report (7h → 8.5 min)
€350 → €7 Labor cost per report
Beta Now field-testing with engineers
Refl.

The failed first test round underscored how important early, methodical testing is for catching technical limitations before a tool goes live. Development itself was challenging, as both SBEC and I had to learn a lot of new things along the way. A clear appetite for this solution has emerged across the organization, given the scale of the time and cost savings. A next step is measuring the indirect time (waiting on others), which ran up to 40 hours per report in the old process and may hold the largest remaining savings potential — still to be measured.

HTML · CSS · JavaScript · Docker · REST API
